# High Score Sports Academy

نسخة تأسيسية قابلة للتشغيل لإدارة الأكاديميات الرياضية. واجهة عربية RTL متجاوبة، خادم Python، قاعدة SQLite، اختبارات لمحرك العمليات. هذه ليست شهادة جاهزية تجارية أو ضمان Zero Data Loss ضد أعطال التخزين.

## نسختان منفصلتان

- **الرابط المنشور**: تجربة واجهة ببيانات افتراضية في localStorage داخل المتصفح؛ ليست قاعدة مركزية، ولا تطبق صلاحيات أمنية، ولا ترسل رسائل. لا تدخل بيانات حقيقية فيها. بيانات الجهاز لا تنتقل إلى جهاز آخر.
- **الخادم المرفق**: تسجيل دخول بجلسات HttpOnly، كلمات مرور PBKDF2، عزل tenant/branch على الخادم، قاعدة SQLite ومعاملات ذرية. تبدأ قاعدة التشغيل خالية من الأطفال والمدربين التجريبيين.

## التشغيل على Windows / PowerShell

ثبّت Python 3.11 أو أحدث، ثم فك ضغط المشروع وافتح PowerShell في مجلده:

```powershell
$env:TIJARO_ADMIN_EMAIL = "admin@your-academy.com"
$env:TIJARO_ADMIN_PASSWORD = Read-Host "Choose an initial password (12+ characters)"
python server.py
```

افتح http://127.0.0.1:8000 وسجل الدخول بالبريد وكلمة المرور اللذين حددتهما. لا توجد كلمات مرور جاهزة داخل المشروع. كلمة المرور الأولية تُستخدم عند إنشاء قاعدة البيانات لأول مرة فقط. في أجهزة Windows التي لا تحتوي قاعدة المناطق الزمنية، ثبّت `tzdata` عبر `python -m pip install tzdata`.

Linux/macOS: اضبط المتغيرين نفسيهما ثم `python3 server.py`. الخادم يستمع محليًا فقط. لا تفتح خادم التطوير مباشرة للإنترنت.

## خطوات بدء العمل

1. من الإعدادات أضف الفروع.
2. من الموظفين أضف المدربين والموظفين وحدد الدور والفرع ونظام الأجر.
3. من الجداول أضف المجموعات. تظهر فقط قائمة المدربين المتاحين ويعاد فحص التعارض في الخادم.
4. أضف المتدربين والاشتراكات. اختر الرياضة ثم المستوى ثم المجموعة المتاحة.
5. سجّل حضور اليوم من حساب المدرب أو الاستقبال. الحضور يخصم حصة، والغياب لا يخصم.
6. افتح ملف الطفل للنقل أو التجديد أو الأرشفة أو الحذف المؤقت أو الاستعادة أو التقييم.
7. ولي الأمر يمكنه إنشاء حساب وطلب تسجيل من شاشة الدخول. الطلب لا يحجز مكانًا حتى يعتمد الاستقبال الاشتراك. بعد الاعتماد يظهر الطفل بحساب ولي الأمر. البريد غير موثق آليًا؛ يجب على الفرع التحقق من هوية مقدم الطلب.
8. وضع الاستقبال على الخادم يسجل خروج الموظف ويفتح التسجيل العام حتى لا تكشف شاشة التابلت لوحة الموظف. حساب موجود يريد إضافة طفل آخر يحتاج مراجعة الاستقبال في هذه النسخة.

## المعمارية

واجهة HTML/CSS/JavaScript بلا تبعيات بناء. الخادم Python standard library. الجداول: tenants, branches, users, sessions, groups_data, children, memberships, subscriptions, attendance, transfers, evaluations, staff, staff_logs, adjustments, outbox, audit, registrations.

كل أكاديمية tenant مستقل. Super Admin مدير كل الفروع داخل أكاديميته، وليس مدير منصة يستطيع قراءة عملاء آخرين. إنشاء أكاديمية جديدة إجراء مشغّل خارج واجهة الويب:

```sh
python manage.py tenant --name "Academy Two" --email "owner@example.com"
```

يطلب كلمة مرور المسؤول دون طباعتها. يحصل العملاء على tenant من حسابهم الموثق؛ لا يؤخذ tenant من بيانات طلبات الإدارة. لكل واجهة تسجيل عامة اضبط TIJARO_DEFAULT_TENANT بمعرف الأكاديمية واستضافة/مسار مستقل. الافتراضي `academy`.

## ضمانات محرك النقل

عملية النقل ضمن `BEGIN IMMEDIATE` في الخادم. تفحص الصلاحيات والسعة، تغلق العضوية القديمة، تنشئ عضوية جديدة، وتضيف سجل نقل وتدقيق. الحضور يحتفظ بمراجع الطفل والعضوية والمجموعة والاشتراك وقت الحصة. لا يعاد كتابته عند النقل. UID ثابت. الاشتراك ورصيده يبقيان كما هما في النقل العادي. التجديد مع النقل عملية ذرية واحدة؛ فشل أي جزء يلغيها كاملة. القيد الجزئي يمنع عضويتين حاليتين للطفل. الأرشفة والحذف المؤقت يغلقان العضوية دون حذف التاريخ.

هذه النسخة تسمح بمجموعة حالية واحدة لكل طفل وبسجل حضور واحد لكل طفل في اليوم. تعدد الرياضات المتزامن، حصص التعويض، النقل المؤجل، وتصحيح حضور مع عكس رصيد ليست منفذة.

## السياسات الحالية

- مستويات السباحة سبعة حسب القائمة المطلوبة: Level A, Level B, Level 1, Level 2, Level 3, Level 4, Level 5.
- أيام الأسبوع تُخزن Monday=0 … Sunday=6. تاريخ العمليات يعتمد Africa/Cairo.
- التجديد له بداية ونهاية محددتان. إذا كانت البداية مستقبلية، يظل الاشتراك القديم قابلًا للاستخدام حتى البداية الجديدة. لا تتغير التواريخ التعاقدية القديمة؛ يسجل superseded_on تاريخ الاستبدال الفعلي. لا يُرحل الرصيد تلقائيًا.
- الانتقال بين فرعين يتطلب Super Admin؛ جميع حسابات الموظفين بما فيها المدير المالي مقيدة بفرع واحد. حساب المتدرب مرتبط بطفل واحد فقط، ويتبعه عند النقل.
- تقييم 80% يقترح مراجعة الترقية؛ الترقية الفعلية تتم بالنقل إلى مجموعة المستوى الجديد.
- ثابت/ساعة/حصة؛ الغياب لا يخصم من الراتب الثابت تلقائيًا. الخصومات والمكافآت تتطلب سببًا، والقسيمة حسابية لا تثبت صرف راتب.
- الأسعار بالجنيه المصري، وبدون ضريبة/فواتير ضريبية أو دفع إلكتروني.
- UID مبني على UUID عشوائي مع قيد PRIMARY KEY يمنع ازدواج التخزين؛ التصادم النادر يرفض العملية ولا يكتب فوق طفل آخر.

## الأمن والصلاحيات

PBKDF2-HMAC-SHA256 بمِلْح منفصل، توكن جلسة عشوائي مخزن بصورة SHA256، جلسة 8 ساعات، SameSite=Strict، منع طلبات النماذج الخارجية عبر X-Tijaro-Request مع عدم تمكين CORS. حد محاولات دخول داخل العملية الواحدة، وليس حماية موزعة. اضبط TIJARO_HTTPS=1 فقط وراء HTTPS ليضاف Secure للكوكي. سجل تدقيق للعمليات الإدارية. طلبات الكتابة تستخدم معاملات SQLite وتتحقق من tenant والفرع والمجموعة في الخادم.

## الاختبارات


اختبارات المنطق تغطي: احتفاظ النقل بالحضور والرصيد، منع الحضور المكرر، الغياب دون خصم، امتلاء المجموعات، تعارض المدربين، عزل الأكاديميات والفروع، منع المدرب من النقل، تفريغ المقعد بالأرشفة، التراجع عند فشل التجديد مع النقل، نطاق حساب ولي الأمر، وانتهاء الاشتراك. اختبار JavaScript يتحقق من توليد الشاشات، العمر قرب نهاية الشهر، التسجيل والنقل والأرشفة. لا تحل هذه الاختبارات محل مراجعة أمنية أو اختبارات تحميل.

## النسخ الاحتياطي

```sh
python manage.py backup academy-backup-2026-09-30.sqlite3
```

يستخدم SQLite backup API لأخذ نسخة متسقة. انسخها إلى تخزين مشفر منفصل مع سياسة احتفاظ واختبار استعادة. قاعدة البيانات والنسخ لا تدخل مستودع Git. النسخ الاحتياطي الدوري والاستعادة الآلية غير مربوطين بخدمة استضافة بعد.

## ما يلزم قبل البيع التجاري

1. نشر الخادم على استضافة مناسبة خلف HTTPS مع قاعدة مركزية مستمرة. الانتقال إلى PostgreSQL ومهاجرات مُنسّخة مطلوب عند التوسع والعمليات المتزامنة الأعلى؛ SQLite هنا نواة مرجعية.
2. ربط WhatsApp Business/مزوّد معتمد، أسرار، قوالب معتمدة، موافقة ولي الأمر، عامل إرسال مع retries/idempotency وwebhooks تسليم. outbox هنا يُسجل الأحداث فقط وحالته unconfigured؛ لا توجد رسائل مرسلة.
3. ربط بريد للتحقق واستعادة كلمة المرور والتنبيهات، وإضافة MFA وإدارة الجلسات الفردية. إدارة الحسابات والأدوار الأساسية وتغيير بيانات الحساب أصبحت موجودة. إنشاء حساب ولي أمر موجود للطفل الثاني وإجراءات تغيير ولي الأمر بحاجة توسعة.
4. مراقبة وتشغيل ونسخ احتياطي مجدول، فحص أمني واختبارات تحميل واستعادة، ضوابط الخصوصية والاحتفاظ ببيانات القاصرين.
5. فوترة SaaS لكل أكاديمية وباقات ترخيص، الدفع الإلكتروني، سياسات التجميد والاسترداد والضرائب، وتقارير المحاسبة التفصيلية.
6. سياسة أكاديمية نهائية لحصص الغياب، الرصيد المرحّل، الرواتب، والتقييم. ليست هناك عملية صرف أو تكامل بنكي.

المصدر المرفق يقدم نواة فعلية وتجربة UI، ولا يدّعي أن المتطلبات التشغيلية الخارجية أصبحت متصلة أو أن النظام جاهز للبيع دون هذه المرحلة.


## تحديث الإدارة 2 — High Score

- الصفحة الرئيسية الآن جدول الإدارة الأسبوعي/اليومي: صفوف الساعات وأعمدة الأيام، أسماء المتدربين داخل كل مجموعة، المدرب، الرياضة والمستوى، رصيد الحصص، السعة، وفلاتر الفرع/الرياضة/المدرب/الاسم. اختيار التاريخ يعرض التوزيع الحالي للجداول المتكررة؛ ليس لقطة تاريخية أو توقعًا محاسبيًا لتوزيع المستقبل. سجل الحضور نفسه تاريخي داخل الملف.
- النقر على الطفل يفتح الملف؛ النقل والتجديد من الملف، وزر نقل مباشر أمام الاسم. إدارة المجموعة تسمح بتغيير المدرب والأوقات والأيام والسعة، مع فحص التعارض والسعة في الخادم. نقل الطفل هو المسار لتغيير فرعه أو رياضته أو مستواه.
- الحسابات والصلاحيات: الأدمن ينشئ حسابات Admin/Manager/Reception/Coach/Finance/Parent/Student، ويعدل الاسم والإيميل والفرع وحالة الحساب وكلمة المرور. لا تُعرض كلمات المرور. التعديل يلغي الجلسات الحالية، وتغيير كلمة مرور الأدمن نفسه يتطلب كلمة مروره الحالية. لا يمكن تعطيل النفس أو آخر أدمن. لا يمكن نقل أو تعطيل مدرب قبل إعادة إسناد مجموعاته.
- يمكن إنشاء حساب المتدرب من ملفه أو شاشة الحسابات؛ لا يرى أي طفل آخر. البريد هو اسم دخول وليس صندوق بريد مُنشأ لدى Google أو Microsoft.
- أسعار الفروع: باقات مستقلة لكل فرع/رياضة/مستوى تشمل عدد الحصص والمدة والسعر. السعر وعدد الحصص يؤخذان من قاعدة البيانات، لا من الحقول التي يرسلها المتصفح. التسعير اليدوي مسموح للأدمن فقط. تعديل الباقة ينشئ نسخة جديدة ويحتفظ بمبالغ العقود القديمة.
- تاريخ بداية ونهاية في التسجيل والتجديد والاشتراكات وملف الطفل. الحضور قبل بداية الخطة مرفوض. التجديد مع النقل يعمل في اليوم الحالي؛ النقل المستقبلي غير منفذ.
- وضع التابلت: قائمة مخصصة وزر علوي لتوسيع الجدول وأزرار اللمس. وضع استقبال منفصل يسجل خروج الموظف على الخادم. `?view=tablet` يفعّل العرض الواسع؛ لا يتجاوز تسجيل الدخول.
- الشعار المؤقت HS؛ لم يتم استلام الشعار الرسمي بعد.
- الترقية تلقائية عند تشغيل الخادم. migrations.py يحفظ نسخة قاعدة قبل إعادة بناء قيد أدوار المستخدمين القديمة، ويحتفظ بالسجلات والمفاتيح الأجنبية. يجب الاحتفاظ بنسخة مستقلة قبل أي تحديث تشغيل.
- 22 اختبار Python إضافة إلى اختبارات JavaScript ومسار HTTP للتسجيل والاعتماد وحساب ولي الأمر.

أسماء الفروع وأسعار الديمو افتراضية قابلة للتعديل. مفاتيح البيئة TIJARO_* ومسار قاعدة البيانات الحالي محفوظة للتوافق مع الإصدار السابق؛ تغيير الاسم التجاري لا يغيّر بيانات الدخول الموجودة.
